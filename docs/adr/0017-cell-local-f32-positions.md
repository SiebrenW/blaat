# Positions are f32, stored relative to their Cell's origin

Every Cell has an origin in World coordinates, and Entities, Static instances, and Terrain inside it store f32 positions relative to that origin. We chose this over f64 world positions because f64 doubles position memory and bandwidth for millions of Static instances (ADR 0013), GPUs and the physics library work in f32, and the per-Cell storage already gives every item a natural local frame (ADR 0009). The loaded neighbourhood is simulated and rendered in one f32 space rebased close to the camera, so precision is a function of distance from the origin and not of the World's size. A Cell must be small enough that f32 precision inside it is adequate; the Cell size is chosen in the world storage milestone against that limit. Moving an Entity between Cells re-expresses its position in the new origin, which is accepted because it is rare (ADR 0009).
