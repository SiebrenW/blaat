# Physics uses Box3D, pinned, behind the Engine; Rapier is the fallback

Box3D (C17, MIT) is the chosen rigid body library because it was faster than Rapier on every solver benchmark we ran, except a tie on the single-threaded joint grid. Both were built with release optimizations and run on the same machine (Apple M5 Pro, one-thread and multi-thread) on Box3D's own `large_pyramid`, `many_pyramids`, and `joint_grid` scenes, ported identically to Rapier 0.36 (4 substeps, 60 Hz, friction 0.6, sleeping off). Box3D took 618 / 677 / 439 ms single-threaded against 1102 / 1256 / 444 ms for Rapier built with fat LTO, one codegen unit, and native CPU; with 8 threads it took 186 / 151 / 104 ms against 351 / 300 / 141 ms. Optimization flags change Rapier by 2 to 12 percent, so they do not explain the differing figures published elsewhere; those come from benchmarks run through Godot bindings. Box3D also has height fields (ADR 0012), a character mover, and lets the host supply the task system, which keeps physics on the Engine scheduler (ADR 0010).

Box3D is version 0.1, accepts no pull requests, and has little documentation, so it is vendored at a pinned tag and used only inside the Engine, never exposed to Game modules except through the SDK. Scene queries were not measured here, and published Godot-addon numbers have Rapier ahead on them, so a spike with a query-heavy scene, a height field, and the character mover is required before the physics integration milestone is built; if Box3D loses materially there, Rapier replaces it. The Rust to C boundary is the cost of the choice.

Both libraries used SIMD in these runs, which were on NEON only. Box3D with SIMD disabled took about 1050 ms on the single-threaded pyramid scenes against 618 and 677 ms with it, so the library's lead is not only SIMD. Rapier's 4-lane `wide` SIMD cannot be switched off, so no scalar comparison exists for it, and its use of NEON was not inspected. Rapier's optional `simd8` feature changed single-threaded times by under 8 percent on NEON, where it runs as two 128-bit halves. The spike must therefore also repeat the solver benchmarks on the floor machine (Ryzen 7 3700U, x86 with AVX2), with Box3D on its AVX2 path and Rapier with and without `simd8` built for native CPU, because `simd8` may matter there.
