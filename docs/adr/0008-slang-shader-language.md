# Shaders are written in Slang and cross-compiled to SPIR-V, MSL, and DXIL

One source language targets Vulkan, Metal, and D3D12. Slang's interfaces and generics fit an uber shader's material permutations. We chose it over HLSL with DXC and SPIRV-Cross, which chains three tools and produces hard-to-debug MSL. We chose it over Rust-based shader languages, whose ecosystem is younger for the compute-heavy features the Engine needs. Compiling test shaders confirmed 64-bit atomic max and mesh shaders on all three targets, with one Metal limitation: mesh shader vertex outputs must be assigned as whole structs. HLSL with DXC and SPIRV-Cross is the fallback if Slang proves inadequate.

Correction: the earlier test only checked that Slang emitted MSL, not that Apple's Metal compiler accepted it. It does not for 64-bit atomic max. Slang lowers it to `atomic_fetch_max_explicit`, which Metal rejects for `ulong`; Metal only has the non-returning `atomic_max_explicit`, on Apple GPUs from M2. The Engine works around this with a per-target intrinsic in `shaders/include/atomics.slang` (Metal gets the hand-written call, other targets keep Slang's lowering), and the shader build now compiles MSL with the Metal compiler on macOS so such mismatches fail the build. The workaround was run on an Apple M5 Pro and produced the correct maximum in all slots. Because Metal returns no previous value, shaders must not rely on one. Other Slang to Metal lowerings are therefore not trusted until compiled with the Metal compiler.
